## 启动与重启

工作区根目录提供两个双击入口：`启动本机测试.cmd` 启动前后端与 Redis，等网页就绪后用 Edge 新窗口打开首页；`停止本机测试.cmd` 停止本项目的测试服务并保存 Redis 数据。启动成功后可以关闭启动窗口，服务仍在后台运行。也可以在仓库目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-location-local.ps1
```

脚本使用已下载的 Node 26 和已安装的项目依赖，每次启动时先执行数据库迁移并检查结构，补齐新功能需要的数据表，保留已有数据；迁移失败会停止启动并提示查看 `.local-data/migrate-local.stderr.log`。随后在后台运行前后端，并启动或复用本项目 16380 端口的 Redis。重复启动会复用已记录的服务并重新打开网页，缺少的服务会补齐；其它程序占用端口时会提示，避免误关闭它们。停止脚本按 PID、启动时间和项目路径核对进程，只关闭本项目记录的进程树，随后执行 Redis 保存退出；账号、题库、截图和登录配置持续保留。进程记录位于 `.local-data/location-services.json`，前后端日志位于同一目录的 `server-local.*.log` 与 `client-local.*.log`。

本机缺少 better-sqlite3 所需的 C++ 编译环境，因此使用 `.tools/sqlite-shim.cjs` 调用 Node 26 的 SQLite 引擎。此文件仅用于本机兼容，不用于生产部署。数据库是 `server/data/csgofriberg.sqlite3`，素材默认保存在 `data/location-assets`。保留这些目录、`.local-data/location-runtime.json` 和 Redis 数据目录即可保留测试数据；不要删除数据库后期望原管理员仍能登录。第一次使用启动脚本后需要重新登录。

`-CheckOnly` 可以检查 Node、依赖、Edge 和端口，不启动新进程。`-NoBrowser` 可以只启动服务而不打开浏览器。停止服务可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-location-local.ps1`；添加 `-CheckOnly` 只显示将要停止的进程。脚本及本机账号没有修改生产网站。换电脑时需要重新安装运行时、依赖与 Redis，并按项目的 `pnpm create-admin` 流程建立账号。

## 清理本机题库

维护时若只想清空图寻题库、采集点及关联游戏状态，同时保留地图和全部校准历史，可使用 `pnpm --filter server location:reset-local --check --keep-maps` 检查，再使用 `--apply --keep-maps` 执行。需要先停止前后端并保留本机 Redis 运行，沿用启动脚本的数据库和 Redis 环境变量。工具先备份数据库、上传素材和图寻缓存，保留历代地图引用的上传雷达文件；账号及其它游戏不受影响。省略 `--keep-maps` 的完整重置会恢复初始地图，不能用于保留校准的清理。

## 上传一题

1. 登录后进入 **图寻管理 → 题目管理 → 新增题目**。
2. 拖入或选择 PNG/JPG/WebP，等待上传和处理完成。支持 1920×1080、1280×960 等截图，原图宽高均需至少 360 像素，文件上限 16 MiB；上传后直接保留正中心 360×360 像素，保存为 WebP。
3. 选择地图、楼层和题目等级；填写拍摄点编号、采集时间、游戏构建和来源。同一站立点不同朝向使用同一个编号。
4. 直接点击雷达图选择截图对应的答案点位。若需按 CS2 指令辅助定位，可展开“可选：坐标与视角辅助”，粘贴 `setpos_exact X Y Z;setang_exact PITCH YAW ROLL`，也支持普通 `setpos/setang`。这些辅助信息无需填写。
5. 选择难度后保存草稿、送审或审核发布。截图加地图、楼层和答案点位即可成题，不要求实测坐标、视角、构建版本或地图校准。“待审核”本身不会进入游戏，须点击“审核并发布”。

批量制作后可在“题目管理”顶部点击“一键批量发布（N）”，一次发布全部草稿和待审核题目，不受下方地图、状态、难度或搜索筛选影响。已发布、已停用题目不会重复处理。超过 500 道时自动分批请求，完成后刷新列表并显示成功数、失败数及每道失败题目的原因。图片缺失、题目版本变化或地图版本变化的题目会保留原状态，可修复或重新核对后重试。

未完成校准时也可以发布雷达标点题。只有已发布、所属地图开放、地图版本匹配的题目才会进入抽题。校准只用于可选的世界坐标定位辅助，具体记录方法见 [采集与校准指南](location-capture.md)。修改地图几何会产生新版本，旧题目须重新核对并保存到当前地图版本。

## 准备可玩的题库

### 先批量标点，再配图

进入 **图寻管理 → 采集工作台**（图寻管理的默认页面）：

1. 选择地图、楼层并填写批次名称，开启“连续标点”，在小地图上依次点击计划拍摄的位置。每个点会生成固定编号。
2. 点击“保存 N 个待采集点”。采集点保存到数据库，不要求图片、难度或拍摄信息；刷新或重启后可继续。尚未点击保存的点会暂存在当前浏览器。
3. 可导出 CSV 采集点清单，在 CS2 中按编号拍摄。建议将截图命名为完整点号，例如 `tx-12345678-001.png`。CSV 的参考 X/Y 从地图配置推算，不能代替 `getpos_exact` 实测值，也不包含站立高度或拍摄朝向。
4. 回到批量页面，多选截图。同一点位可以对应多张图片，文件名使用 `点号.png` 或 `点号__任意后缀.png`，例如 `tx-12345678-001__easy.png`、`tx-12345678-001__hard.png`，即可自动匹配同一点位。后缀只帮助命名，难度在编辑页分别设置。也可手动选择位置，或点击“按当前点号顺序分配”；顺序分配针对未配图的点，必须核对后再点击“确认并保存配图”。
5. 点击地图编号或右侧列表查看点位的图片列表，点击缩略图选择要完善的图片。“向此点位添加图片”可继续多选追加；“移除此图”只移除该待出题图片。完成题目后，点位和其余图片会保留，可随时继续追加。
6. 每张图单独点击“完善此题信息”，选择难度，核对截图与雷达答案后即可发布；采集时间、构建版本、实测坐标和视角为可选信息。若使用坐标辅助，第一张实测题目确定共用世界坐标，后续图片沿用该位置。“保存草稿并完善下一题”优先编辑同点位的下一张图片。
7. 已生成题目也可在“题目管理”点击“同点位新增图片题”，上传新图并单独选择难度和视角。旧题目不会被覆盖。所有图片题按共同点位去重，同一局只抽其中一张，每日三个题单也不会重复同一点位；多张图不等于多个可用站位。

“新建采集批次”创建独立批次和点号，不清除其它批次未保存的点。切换到题目管理、地图管理等页签时，采集工作台保持挂载，已选择但尚未上传的截图不会因切换页签丢失。“题目管理”支持按地图、难度、状态与点号搜索；目录 JSON 导入收纳在“题库备份与迁移”的高级导入区域。

同一地图的不同采集批次使用不同标点底色，点位列表同步显示批次颜色、名称和简短编号，同名批次也可区分。点击地图上方的批次图例或“查看批次”可筛选，尚未保存的点也遵循筛选；查看单个批次时会关闭连续标点，重新开启后恢复全部批次。黄色高亮外圈表示未配图且未出题，青色虚线外圈表示仍有图片待出题（包括已有题目但还有剩余图片的点位），已有题目且没有剩余图片时不显示状态外圈。选中点位保留批次底色，额外显示蓝色选中圈；鼠标悬停可查看批次、点号和状态。

“地图管理”根据全部实测基准点自动计算原点和比例，不使用预设参数作为约束。页面显示逐点拟合偏差和各层基准点数量，原点与比例为只读结果；服务端保存时独立重算，高级 JSON 中手填的旧参数也不会覆盖实测拟合。每层至少三个分散、不共线的点，计算后每点偏差不超过 0.5% 才算通过。已有基准点无需重录，打开地图管理并保存即可应用新计算。几何更改产生新版本，旧采集点需在编辑页重新核对位置并确认。“题库检查”按需检查图片和实际抽题条件，编辑页刷新不会再扫描全部图片。

保存失败的配图保留在列表中，可调整后重试；已成功保存的不会重复上传。完整题库 ZIP 同时包含未配图采集点、已配图半成品及其图片，旧版题库 ZIP 仍可导入。

已保存的题库会持续保留，不需要每次启动重新上传。若要备份、换电脑或随首发上线，使用“图寻管理 → 题库备份与迁移”的完整 ZIP 导出和导入，见 [题库迁移说明](location-bank-transfer.md)。

完成游戏后，在首页“统计/回放”切换到“图寻”，可按难度查看个人和全站统计，并切换单人／多人战绩；单人还能筛选随机或每日模式。图寻游戏内的战绩入口也跳转到同一页面。点击“回放”后，顶部五张缩略图可切换轮次，显示当时的场景截图、正确答案、玩家落点、偏差和得分；截图可点击放大，多人局支持切换玩家。回放保留对局当时的地图和题目快照。

每局固定五题，配比不能用重复题补足。测试普通随机局至少准备 **2 易、2 中、1 难**，并使用五个不同拍摄点；简单为 3/1/1，困难为 1/2/2。当日挑战使用的拍摄点会从新随机局和多人局中排除，若还要同时测试每日和随机，请额外准备题目。

三个每日难度合计至少需要 6 易、5 中、4 难，题目与站立点相互独立。题库不足会显示明确提示。草稿上传成功不代表题库已经可开局；请先在“题库检查”核对配比和发布状态。

真实 CS2 截图和拍摄坐标由采集者提供。界面验收使用的合成测试图片与草稿已清理，没有作为正式题目发布。
