## 2026-10-17 采集流程重构

后台默认进入采集工作台；题目筛选、地图表单、完整性检查、每日题单和备份导入分别由独立组件负责。`AdminLocation` 只负责页签和编辑窗口，采集与单人游戏的状态处理位于各自 hook。后台样式已移到 `client/src/components/admin/location/admin.css`，不再混入玩家页面样式。

服务端 `location/routes.ts` 保留玩家 HTTP 接口，`location/admin/routes.ts` 处理管理接口；`maps.ts`、`questions.ts`、`captures.ts` 和 `overview.ts` 分别负责地图版本、题目发布、采集计划和按需检查。前后端共享 `types.ts` 与纯坐标转换 `coordinates.ts`；数据库检查和本机清理共用 `schema.ts` 中的数据表清单。新增表需同步此清单，测试会检查清单完整性。

## 自动化覆盖的主要行为

- 严格三档题数、独立站立点、关闭地图及当日每日拍摄点排除、配比不足拒绝开局。
- 用户规定的四个评分样例、错地图零分、正确图最低一分、0.5% 容差、矩形雷达尺寸、错层 25%。
- 每层实测校准检查、坐标越界/不一致、资源哈希与去元数据、重复发布阻止、地图/题目不可变版本、旧版本请求拒绝。
- 随机恢复、幂等答案、身份隔离；每日三个独立题单、放弃重开、逐轮保存、交卷前隐藏结果、并发交卷唯一战绩、到期拒绝及上海零点计算。
- 多人同题五轮、全员提交统一揭晓、未揭晓时不显示他人答案、双人匹配、超时、30 秒断线规则、重连恢复、退赛与全员退赛取消、同分并列、唯一终局成绩。
- 前端雷达缩放/视口变化不改归一化坐标、拖动不落点、多层明确选择、切地图清空落点、每日提交结果保密、上传窗口解析与草稿保存、超大图片拒绝。
- 原有猜选手、海龟汤、身份认证、后台、每日、统计、排行榜、PoW 与 Socket 测试一并通过。

## 验证环境与限制

本机 Windows、Node 26.10.0、Redis 8.10.2。由于本机缺少 C++ 构建环境，Knex 的 SQLite 测试通过本机 `.tools/sqlite-shim.cjs` 接到 Node 26 的真实 SQLite；并发演练使用 WAL 和 5 秒 busy timeout。两个实例是实际独立 Node 子进程，通过 Redis adapter 协作，使用隔离的测试数据库和 Redis 前缀。测试并未模拟成单个进程中的两份对象。

该结果证明本机双进程逻辑通过，**尚未验证生产 PostgreSQL、Docker 容器或生产共享卷**。演练主要比赛保留正常 3 秒准备和 8 秒结算展示；额外超时/退赛测试直接调整隔离状态中的截止时间，以覆盖分支，不属于真实 120 秒等待或断网硬件测试。

手机检查为浏览器视口与指针自动化；真实手机、多点触控硬件、实际网络波动和系统横竖屏切换还需要上线前设备验收。三语文案已维护、双主题已接入，尚不能将全部页面的人工三语/双主题验收记为完成。客户端构建有既有 Socket 模块静态/动态导入提示，构建成功。
