首次部署图寻时，可直接在后台导入 `location-bank.zip`；或先将它复制为 `.local-data/location-release/initial-bank.zip`，执行下方 Compose 预览和导入命令。不要把 `content.sqlite3` 覆盖到现有数据库，也不要对已有线上数据执行全表替换。卡牌资料与图的目标环境迁移应先核对稳定 ID；公开归档保留了源数据，不代表已经修改线上玩家库。

后台上传的图片立即保存至素材目录；点击“保存草稿”“待审核”或“审核并发布”成功后，题目写入数据库。刷新和重启应用不会清空已保存的内容。尚未点击保存的表单输入不会自动成为题目。保存与导出是独立操作，无需先导出才能保留题库。

本机数据库为 `server/data/csgofriberg.sqlite3`，素材默认在 `data/location-assets`；生产使用 PostgreSQL 和 `LOCATION_ASSET_DIR` 指定的共享持久卷。删除数据库、素材目录或持久卷会丢失对应数据，普通 Docker 镜像更新应保留持久卷。

## 后台导出与导入

进入 **管理员后台 → 图寻管理 → 题库备份与迁移**。

- 点击“导出完整题库 ZIP”，下载当前题库。包内包含所有当前题目，包括草稿、待审核、已发布、已停用，以及截图、缩略图、真实雷达、楼层、校准点、采集信息和这些题目引用的地图版本。
- 在同一台电脑、另一台电脑或上线环境选择“导入题库 ZIP”。文件无需手工解压、逐张上传或重新标注，先显示数量及冲突检查结果，此时不改数据库。
- 完整相同的题目自动跳过。相同题号、不同内容默认阻止导入；确实要更新时勾选“允许把同编号的不同题目更新为新版本”，重新检查后确认。相同图片绑定不同题号不能直接导入，应整理源题库。
- 点击“确认导入题库”后，地图配置、题目和版本在一个数据库事务中保存；失败不会留下半份题库。重试相同导入不会重复创建题目。
- 导入保留审核状态。已发布题目只需有效图片和地图答案，不要求校准、实测坐标或视角；导入不会把未经审核的草稿变为已发布题目。
- 地图变更创建新版本，旧题目引用的地图快照一并保留。来源题库中已经过期的地图引用仍保持过期，不能借导入绕过重新校验；目标端未包含在包内的旧题目也可能需要重新校验。
- 预览有效期为 30 分钟。预览后若有其他管理员修改题库，应点击“重新检查”，避免应用过时结果。每个管理员每小时最多上传 6 个 ZIP。

上限为 1 GiB ZIP、单素材 16 MiB、当前题目 5000 道。服务端流式接收 ZIP 并在共享目录的私有临时子目录 `.bank-transfer` 中验证，校验文件哈希、实际 WebP 格式、雷达尺寸、坐标、楼层、路径和缺失素材。发布素材使用不可变文件，不覆盖旧 URL。临时数据不会加入公开图片目录索引，过期临时目录在后续上传时清理。

## 原始题库随首发上线

建议流程：**本机制作 → 校准与人工审核 → 导出 ZIP → 预发布环境导入 → 五轮测试 → 生产部署时导入 → 对外开放**。原始题库作为发布附件与代码、镜像和部署记录一起保留，数据库和图片仍使用持久存储。正式题目不需要写死到前端代码中。

除了后台导入，还提供运维命令，适合在首次部署开放访问前初始化题库。命令使用当前环境的数据库、Redis 和素材目录配置；在生产执行前核对这些配置和备份。路径请使用绝对路径：

```powershell
pnpm --filter server location:export "F:/CS-guesser猜位置小游戏/.local-data/initial-bank.zip"
pnpm --filter server location:import "F:/CS-guesser猜位置小游戏/.local-data/initial-bank.zip" --check
pnpm --filter server location:import "F:/CS-guesser猜位置小游戏/.local-data/initial-bank.zip"
```

`--check` 仅显示检查结果；确实需要更新同编号内容时加 `--update-existing`。导出文件已存在会报错，避免覆盖备份。Windows 本机命令需使用 [本机运行环境](location-local-testing.md) 中的 Node 与 SQLite 兼容配置；生产不使用本机兼容 shim。

生产镜像内没有 pnpm/tsx，因此 Compose 增加默认不开启的 `location-bank-import` 运维服务。把正式 ZIP 放到 `.local-data/location-release/initial-bank.zip`，或通过 `LOCATION_BANK_FILE` 指定宿主机上的绝对路径；它使用与应用相同的数据库、Redis 和共享素材卷：

```text
docker compose --profile location-tools run --rm location-bank-import server/dist/location/importBank.js /release/initial-bank.zip --check
docker compose --profile location-tools run --rm location-bank-import
```

服务把 ZIP 作为只读发布附件挂入 `/release/initial-bank.zip`，共享素材卷仍以现有非 root 身份写入；文件不存在时不会把它偷偷建立成目录。导入完成后，从两个实例读取样图并验证新随机局与每日题库配比，再开放首发入口。本机没有 Docker，因此该运维服务仅通过配置静态检查，尚需在预发布环境实测；没有在本机将 ZIP 导入生产。

## 题库包与整站备份

题库包用于制作成果的搬运和备份，包含答案。它不包含管理员账号、玩家身份、个人战绩、每日题单、活跃房间，也不保存已经被后续题目版本替代的所有历史截图。完整灾难恢复仍应同时备份数据库、整个素材卷及所需 Redis 快照，方法见 [部署与备份说明](location-deployment.md)。游戏内处理后的 WebP 随包导出，采集用原始 PNG 和控制台记录仍由采集团队另外保管。

可在每批题目制作或审核完成后导出一个按日期保留的 ZIP，上线时固定其中一份作为首发题库。尚未采集的 500 道真实题目不会自动生成。
