# 图寻题目投稿

## 入口与操作

图寻菜单的“图寻题目投稿”进入 `/entertainment/location/submit`。玩家和游客均可使用，无须绑定邮箱。2026-10-29 起支持连续标点、同点多图和批量送审，单张投稿仍可直接使用。

1. 选择地图和楼层，开启“连续标点”，依次标出物体或墙面的位置。每个点位保留独立编号；点击已有编号可选择它，“调整当前点”用于移动尚未送审的点。
2. 选中编号后一次多选或拖入截图，也可继续追加。同一物体或墙面的不同视角可以共用一点；不同物体应分别标点。点击文件名检查中央裁剪，“此图对应点位”可改配某一张图片，补充说明也按图片独立填写。
3. 点击“提交投稿”依次上传所有未完成图片，每张图片单独审核。显示当前进度、已送审和失败状态；成功图片释放原 File，后续提交不会重复发送它。断网、限流或服务异常会暂停剩余队列，保留文件供重试；结果不明的请求固定 UUID、点位和说明，防止重试变更内容。

每页最多 100 个点位；未提交队列最多 30 张、256 MiB。切换地图/楼层保留本页全部点位与图片；这不是跨页面草稿库，离开或刷新前应完成提交。存在未提交图片时添加浏览器关闭/刷新提示，页面也明确说明此边界。移出本页队列不撤回已送审的投稿，删除空点不会删除已提交题目。桌面并排展示雷达、图片与规则；手机单列。

出题页面始终提供规则栏，桌面端在右侧随页面滚动保持可见，窄屏在上方保留可滚动的规则区域。规则强调练习模式、无限热身、格洛克等短枪、适当分辨率、物体与墙面位置、偏差和准星大小，并补充原图、重复图片和审核要求。

截图支持 PNG / JPG / WebP，16 MB 以内、宽高均至少 360 像素，总像素最多 1600 万。系统直接截取原图正中心的 360×360 像素，而不是把整张图缩小；提交前显示同样的中央裁剪预览。

标注对象是**图中物体或墙面的位置**，不是截图者的站位。因此投稿页面使用雷达手动标点，不提供把摄影师 getpos 指令自动当答案的入口。地图或楼层切换只改变当前视图，清除当前选中状态，不删除其他地图的点位；图片请求始终携带其绑定点位的地图、楼层与标注时版本。旧版地图会被服务端拒绝，刷新资料并重新核对位置后再提交。

提交后可在页面下方查看当前身份的待审核投稿。拒绝后不保留拒绝历史；采纳数可在图寻生涯统计与图寻圣人榜查看。游客贡献属于当前浏览器的签名身份，登录后随原有“认领访客数据”流程归并。

## 管理员审核

管理后台 → 图寻管理 → 投稿审核。列表展示缩略图、投稿者显示 ID、地图、楼层与说明，可手动刷新。

选择“审核截图与标点”后，管理员可放大截图、修正地图与楼层、调整答案位置，再选择简单 / 中 / 困难难度，并勾选已核对物体或墙面位置。

2026-10-29 增加“显示已有点位”和“并入已有点位”：

- “显示已有点位”在当前地图/楼层雷达上显示已有题目的编号，可随时隐藏。默认关闭，只有显示或准备并入时才加载该地图的数据。
- 勾选“并入已有点位”后，点击雷达编号或在“要并入的点位”列表中选择目标，页面显示目标编号、答案和最多三张示例截图；示例截图可放大核对。尚未选择有效目标时不能采纳。此时答案由目标点位决定，不能拖动修改；取消并入后恢复本题此前的人工标点。
- 隐藏编号不会取消已选目标，也不改变答案；切换地图/楼层、重新加载点位、修改目标会清除复核勾选。切换地图/楼层还会清除目标，过期请求不会把旧地图的点位带回来。
- 采纳后只新增这张投稿对应的题目和贡献，复用目标 `capturePointId` 及现有答案（有实测 XYZ 时一起继承），不新建点位、不移动或改写已有题目与采集草稿。只含未制作采集草稿的点不是本入口的候选；旧地图版本或跨楼层异常目标不能选用。
- 目标在预览后被编辑、增加图片或合并移走时，服务端要求重新加载核对，保留待审核投稿与截图，不把消失的点重新创建。普通新点发布和拒绝流程继续保留。

- **采纳并发布**：同一事务中创建正式 `location_questions` 题目和版本快照、记录一次贡献、删除待审核记录。管理员可以在原“题目管理”中继续编辑、停用、发布等操作。来源字段标记投稿者显示 ID。
- **拒绝并删除**：确认后删除待审核记录及其专属截图和缩略图，不计贡献。不会生成正式题目或版本快照。
- 地图版本变更后，审核需要刷新当前地图、重新核对位置，防止旧点位静默套到新雷达上。

## 统计与排名

图寻“个人统计”和“全站统计”新增“题目被采纳数（累计）”，不随游玩难度筛选改变。每道采纳投稿计一次；正式题目后续编辑、停用或删除，不撤销历史采纳贡献。

排行榜新增“图寻圣人榜”，玩家与游客共同按累计采纳数降序排列，同数并列排名，并提供当前身份的数量与排名。每页 50 人。沿用账号隐藏排行设置；被封禁的账号和游客不上榜。榜单不会返回可用于登录的访客 key。

原有管理员直接创建的题目没有投稿审核来源，不追溯生成贡献。新增游客归并会同时迁移待审核记录和已采纳贡献，多次认领不会重复计数。

## 数据与接口

新增 `location_submissions` 保存未审核投稿，`location_contributions` 保存已采纳贡献。后者不依赖正式题目删除，保证累计统计持久。已有题库和战绩不做重置，迁移可重复执行。本机修改前的备份为 `.local-data/backups/before-community-submissions.sqlite3`。

| 接口 | 行为 |
| --- | --- |
| `POST /api/location/submissions` | 每张截图原始二进制；查询参数为 UUID `id`、`mapId`、`floorId`、`u`、`v`、`mapVersion`、可选 `note` 和可选 UUID `pointId` |
| `GET /api/location/submissions?page=1` | 当前身份的待审核列表，每页 12 条 |
| `GET /api/location/submissions/leaderboard?page=1` | 图寻圣人榜，含当前身份数量与排名 |
| `GET /api/admin/location/submissions?page=1` | 管理员审核队列 |
| `POST /api/admin/location/submissions/:id/review` | `decision=reject`，或 `decision=approve` 加位置、地图版本、`tier` 及 `verified=true`；并入已有点时额外传 `existingPoint: { capturePointId, fingerprint }` |
| `GET /api/admin/location/submission-points?mapId=...&floorId=...` | 管理员专用的当前地图/楼层已有题目点位摘要、示例截图及内容指纹 |

公开接口沿用 PoW、签名游客 / 登录身份及封禁检查。截图提交在通用 64 KiB JSON 限制之前单独解析，限制为 16 MiB；2026-10-29 调整为每身份每小时 60 次请求、每 IP 每小时 120 次、每身份最多 100 条待审核，使批量投稿可实际使用。客户端逐张上传，仍受原图片请求与解码工作预算限制。常量位于 `packages/location-core/src/submissions.ts`；限流按请求计数，包括重试。

提交 UUID 与图片、位置等请求内容绑定，重复请求返回原结果。队列及正式题库同时检查裁剪后的图片哈希。审核使用跨实例锁，发布、贡献记录和队列删除在同一数据库事务内完成；并发采纳或请求重试只计一次。

同点多图复用现有单图接口和审核事务，不新增批量文件请求或 SQL 表。可选 `pointId` 是客户端本次标点的 UUID，不能直接作为正式题库点 ID。服务端把投稿身份、点 UUID、地图版本和坐标计算为隔离的 `capturePointId`，保存在待审核 JSON 中；游客已有投稿被认领时不改变此组。审核后仅同组且最终审核位置一致的图片共用正式点 ID，管理员单独修正某图不会被先采纳的同组图片强制吸回原坐标。旧投稿缺少字段时继续采用原单图点 ID；不回写历史题库。

上述自动分组适用于未选择已有点位的审核。显式并入时，`saveQuestion` 在原 `location:catalog` 锁内检查目标仍有题目、全部题目/草稿指纹未变、地图版本与楼层正确，重新读取规范答案，忽略客户端尝试改动目标的 u/v。版本、贡献和队列删除继续在同一事务中完成，重复审核沿用原贡献回执，不重复计数。点位读取和指纹逻辑与题目合并共用 `admin/pointCatalog.ts`，没有新增数据库表列、复制图片或重写历史。
