# 图寻优化落地记录（2026-10-23）

本轮针对工作区图寻的性能、存储、后台任务和模块边界实施优化。爬虫与选手数据库更新逻辑保留本机版本；没有向 GitHub 发布或部署线上服务。

## 数据保全与实际迁移

完整备份位于 `.local-data/backups/location-optimization-20261023-83ef19ec/`，包括 SQLite 一致性备份、822 个资源文件、Redis 持久化文件、源码 ZIP 和哈希清单。

先在备份副本迁移，再迁移实际数据库 `server/data/csgofriberg.sqlite3`。迁移前后对 27 张原有表逐字段比较，原有值全部一致；822 个资源文件逐文件 SHA-256 一致，SQLite 完整性与外键检查通过。原有内容包括 408 道题、379 个采集草稿、841 条版本记录、6 条战绩、4 份每日题单和 4 份每日进度。没有重生成旧每日题单、重算旧成绩或覆盖旧题目 JSON。

运行本机服务及验收后，再次核对原有图寻记录及所有图片。HTTP 验收读取了管理员已有的 3 份旧回放，地图快照和成绩正常。

核验脚本：

```powershell
python scripts/verify-location-preservation.py --database F:/friberg-ex/server/data/csgofriberg.sqlite3
# 服务运行后允许新增题单等记录，同时核对原有图寻记录：
python scripts/verify-location-preservation.py --database F:/friberg-ex/server/data/csgofriberg.sqlite3 --location-only --allow-additions
```

第一次命令要求所有旧表的行集合完全一致，适合停服迁移核验；第二次允许新增行，但原有行必须仍然存在且字段不变。正常登录会更新非图寻账号活动字段，因此在线核验只比较图寻域。

## 指标与维护接口

以下均要求管理员登录：

- `GET /api/admin/location/metrics`：计数器、耗时均值/P95、图片预算、待结算及人工处理任务数量。
- `GET /api/admin/location/outbox`：最近到期的最多 100 个任务及重试原因。
- `POST /api/admin/location/outbox/:id/retry`：将保留任务重置为可重试。
- `GET /api/admin/location/assets/inventory`：资源引用与隔离候选盘点，仅返回报告。
- `GET /api/admin/location/questions`：分页与矩形范围查询；有范围时必须同时给地图、楼层及完整四个边界。

每个耗时指标只保留最近 256 个采样。资源盘点包含全部历史快照，采取保守引用策略，因此不会为了回收少量空间而删除仍可能用于旧回放的图片。

若回滚，应停止本机服务，并使用匹配的源码、数据库、Redis、资源备份；已在新版本中新建的数据应先另外备份，不能只替换旧源码来读取新格式记录。

## 2026-10-23 后续一致性与调度修正

本节追加后续实现，不覆盖上文历史测试记录。分项实施和验收见 [主手册](PROJECT_HANDOFF.md) 第 17.6 节。

- `resultOutbox.ts` 负责持久结算，SQL due_at 权威；失败后 5 秒起指数退避、最高 5 分钟，10 次后人工重试。Redis 用于唤醒，锁内重新核对 SQL。手工 retry 使用同一锁。
- `maintenanceWorkers.ts` 独立调度结算、删图、归档和日志，防任务重叠并支持关停排空；结算并发 2。归档只处理原规则允许的过期 v2 进度，异步压缩在事务外，短事务再次核对原 payload。
- `/capture-drafts?revision=...` 可返回 `{revision, unchanged:true}`，无版本仍返回完整 items；前端保留此前完整快照，不将部分页当成全量对账。SQL 聚合兼容 asset 与 images 共存。
- `/checks` 新增 randomAfterDaily、dailySource、uniquePoints、reservedPoints、remainingByTier。无今日题单仅模拟，不调用 ensureDaily；模拟结果不保证未来随机生成的题单恰好相同。
- `/metrics` 增加 instance、startedAt、collectedAt、RSS 和累积直方图；最近 256 个样本只用于 P95。每分钟输出 `event=location.metrics` JSON，可按 instance 收集；计数器重启会重置，应按 startedAt 分段。Compose 保留 5 × 10 MB 日志，不等于永久存储或全站聚合。
- 后台“运行状态”按需读取，不设隐藏页轮询；结算重试确认后执行，资源清单始终只读。管理员诊断响应均设 no-store。
- 回放按引用层分批读取，每批最多 100 个快照；缺失及循环引用明确报错，不用当前地图替代历史。
